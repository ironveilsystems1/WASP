#
# A leading dot matches subdomains: .wordpress.org covers api.wordpress.org
# and downloads.wordpress.org. Without the dot the match is exact.

# compromised site, and the reason this control is worth having is that the
# list is short. "A plugin seemed to want it" is how an allowlist becomes a
# formality.
#
# Use discovery to find what a specific site actually needs:
#   wasp-egress discovery report

# ── Container registries, for image updates ──────────────────────────────────
# Needed by update.sh; not by WordPress itself. Removing these means image
# updates must be done from the Proxmox host instead, which is a defensible
# choice for a locked-down deployment.
# .docker.io covers registry-1.docker.io and auth.docker.io. Listing those
# separately is not merely redundant -- squid's dstdomain ACL is a splay tree
# and it treats a subdomain of an already-listed parent as a FATAL config
# error, not a warning:
#     ERROR: 'registry-1.docker.io' is a subdomain of '.docker.io'
#     FATAL: Bungled ... acl runtime_allow dstdomain
# which is what stopped a real production install. Never list both a leading-dot
# parent and any of its subdomains in the same dstdomain file.
production.cloudflare.docker.com
.docker.io
ghcr.io
.githubusercontent.com

# ── NOT included, deliberately ───────────────────────────────────────────────
# Gravatar, Google Fonts, jsdelivr, unpkg, and the rest of the CDN estate that
# WordPress themes reach for. They are usually optional, they are a common
# exfiltration path, and a site that visibly breaks without one is a site
# whose dependency you have just discovered. Add them if a client's site
# genuinely needs them, after discovery has shown it does.

# ── Commercial themes and page builders ──────────────────────────────────────
